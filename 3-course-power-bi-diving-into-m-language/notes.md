# Course: Power BI: Diving into M Language (Mergulhando na linguagem M)

## 1: Introduction to M Syntax and Web APIs

### 1.1. Consuming REST APIs and JSON Payloads via Power Query
Modern data engineering architecture frequently relies on extracting operational data directly from web services. An **API (Application Programming Interface)** acts as a structured contract allowing Power BI to request and ingest live datasets via defined communication protocols.

* **The JSON Data Exchange Standard:** APIs standardly communicate using **JSON (JavaScript Object Notation)**. This lightweight, text-based data format structures information into hierarchical key-value pairs (`Records`) and collection arrays (`Lists`).
* **The Role of the M Engine:** While native JSON data is deeply nested and visually unreadable for relational models, the **M Language (Data Mashup Engine)** provides the programmatic functions necessary to authenticate web requests, establish query parameters, intercept the payload, and dynamically flatten complex nested structures into tabular format.

### 1.2. The Anatomy of M: Structural Blocks and the Advanced Editor
Every data transformation query generated by the Power Query interface compiles under the hood into sequential expression blocks using a functional language paradigm.

* **The Core Structural Blocks (`let` and `in`):**
    * **`let` (The Evaluation Block):** This zone acts as a linear container where data extraction commands, data types mutations, and variables are evaluated. Each operational step behaves as an immutable declaration and must terminate with a trailing comma (except for the very last step preceding the output trigger).
    * **`in` (The Return Block):** Explicitly establishes the ultimate expression or reference step whose evaluated data frame will materialize in the data model.
* **The Blueprint of a Blank Query:**
    ```powerquery
    let
        Fonte = "",
        Personalizar1 = Fonte
    in
        Personalizar1
    ```
* **Development Environment Enhancements:** Utilizing a *Consulta Nula* (Blank Query) serves as the industry-standard clean canvas for advanced developers. Enabling native IDE features inside the Advanced Editor—such as *Line Numbers*, *Render Whitespaces*, and the *Minimap*—aligns the Power Query development workflow with modern programming practices.

## 2: Core Fundamentals of M Syntax

### 2.1. Variables, Escape Syntax, and Variable Scoping (`let` Nesting)
Understanding how the Mashup Engine evaluates references is critical for manual code maintenance and advanced data transformation patterns.

* **Step Names and the Escape Identifier (`#""`):** In M, standard variable names cannot contain spaces or reserved characters. To bypass this restriction, the engine uses the escape syntax `#"Variable Name"`. Once a variable is initialized with this syntax, all downstream step references must preserve the exact identifier format.
* **Global vs. Local Scoping (Nested Functional Blocks):** M supports nested evaluation environments by placing secondary `let...in` blocks inside higher-level variable definitions. 
    * Variables declared in the main level act as **Global Variables** within that query's context.
    * Variables declared inside a sub-block act as **Local Variables**. They are strictly encapsulated; external steps cannot reference them directly, only the output of the sub-block itself is exposed.

* **Conceptual Code (Encapsulation and Concatenation):**
    ```powerquery
    let
        Var1 =
            let
                a = "Power"
            in
                a, // 'a' is local to Var1
        Var2 =
            let
                b = "Query"
            in
                b  // 'b' is local to Var2
    in
        Var1 & Var2 // Compiles successfully into "PowerQuery" by referencing global scopes
    ```

### 2.2. Data Typology and Primitive Type Hierarchy in M
The M Language operates on a strictly defined type system where types act as classifiers for evaluated values. Every single primitive type and abstract definition branches from a root abstract type called `any`.

* **The Type Hierarchy (`any` and `none`):**
    * **`any`:** The universal root classifier. All valid M expressions return a value that conforms to a subtype of `any`.
    * **`anynonnull`:** A specialized abstract subtype classifying all possible values *excluding* `null`.
    * **`none`:** An abstract type representing the empty set; it classifies absolutely no values.
* **The Structural vs. Scalar Split:**
    * **Scalar/Literal Types:** Simple data structures including `text`, `number`, `logical` (`true`/`false`), `null`, and temporal structures (`date`, `time`, `datetime`, `datetimezone`, `duration`).
    * **Complex/Abstract Structural Types:** Unlike traditional programming environments, M promotes macro data structures to primitive types, such as `list` (ordered collections), `record` (fields of key-value combinations), `table` (two-dimensional arrays of rows and columns), and `function` (executable code blocks).

### 2.3. Data Ingestion Layouts: Lists, Generics, and Positional Referencing
The Mashup Engine manages structural arrays through precise notation indicators. Mastering lists and data extraction formats prevents structural syntax breaks when parsing API responses.

* **List Generation Mechanics (`{ }`):**
    * **Manual Lists:** Items explicitly declared inside braces and separated by commas: `{1, 2, 3}`.
    * **Sequential Generators (Intervals):** Uses the `..` operator to incrementally build collections without manual parsing: `{1..99}` or `{"A".."Z"}`.
    * **Nested Collections (List of Lists):** A list container can store multiple list references, such as `mistura = {numeros, alfabeto}`.
* **Extraction Syntax (`Table[Column]{Row}`):**
    * **Column Selection (`[Column]`):** Extracting a specific column from a `table` type variable automatically converts that subset data into a strict `list` layout.
    * **Positional Indexing (`{Row}`):** M utilizes a **zero-based indexing** system. Placing an integer inside braces targets the element residing at that exact offset.

* **The Extraction Drilldown Blueprint:**
    ```powerquery
    in
        #"Tipo Alterado"[Texto]{0} // Extracts the scalar value from the 1st row of the 'Texto' column
    ```
